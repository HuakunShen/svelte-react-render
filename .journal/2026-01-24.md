## Vue 3 Demo & Interop Implementation

### Context
Implemented the Vue 3 demo application (`packages/demo-vue`) to prove the framework-agnostic capabilities of the Svelte-React rendering system. The goal was to achieve feature parity with the SvelteKit and React demos.

### Implementation Details
- **Structure**: Recreated the triple-mode architecture (Worker, Node.js, Main Thread) using Vue 3 Composition API.
- **Rendering**: Built a recursive `ComponentRenderer.vue` that maps the serialized React component tree to Vue components.
- **Interop**:
    - Configured Vite to handle both `.vue` files and `.tsx` (React) files in the same project using `@vitejs/plugin-vue` and `@vitejs/plugin-react`.
    - Implemented a `PluginHost` wrapper to render React components directly in the Main Thread mode.

### Challenges & Solutions
1.  **Event Handling Mismatch**:
    -   *Challenge*: React passes events as props (`onClick`), while Vue uses an event emitter system.
    -   *Solution*: Implemented a translation layer in `ComponentRenderer` that maps `_onClickHandlerId` props to native Vue `v-on` listeners.

2.  **Controlled Component State Sync**:
    -   *Challenge*: `reka-ui` components (`Switch`, `Toggle`) weren't propagating state changes back to the React plugin reliably in the Worker/RPC context.
    -   *Solution*: Added explicit `@click` handlers as fallbacks to ensure events are always emitted to the worker, regardless of internal component state logic.

3.  **JSX Type Conflicts**:
    -   *Challenge*: `vue-tsc` struggles with mixed React/Vue JSX types in the same project.
    -   *Decision*: Accepted CLI type-check warnings for now, as runtime behavior is correct. Future work could involve separating tsconfigs more strictly.

### Outcome
The Vue demo is fully functional, supporting all three runtime modes and correctly rendering complex interactive React plugins using Vue UI components.
