### Problem 1: Plugin Stuck on "Loading plugin..."

**Symptom**: The React plugin would never render. Console logs showed the reconciler was creating instances and setting rootInstance, but the Svelte UI remained stuck on the loading screen.

**Root Cause**: The `appendChildToContainer` function in the reconciler was using nested `setTimeout` calls to defer setting `rootInstance` and calling `update()`. This was intended to ensure operations ran after `clearContainer`, but it created a timing issue where:
1. The rootInstance was set asynchronously
2. The update callback was called in another setTimeout
3. By the time these ran, React's render phase had already completed

**Investigation Trail**:
- Console logs confirmed reconciler was working: `createInstance` and `appendChildToContainer` were being called
- `PluginHost.svelte` bridge subscription was triggered
- `rootInstance` was being assigned in the Svelte state
- But the `{#if rootInstance}` block never evaluated to true

**Solution**: Made `appendChildToContainer` synchronous by removing all setTimeout calls:
```typescript
appendChildToContainer(container: Container, child: Instance): void {
  console.log('Reconciler: appendChildToContainer', { childId: child.id, childType: child.type });
  container.rootInstance = child;
  console.log('Reconciler: rootInstance set, calling update');
  container.update();
  console.log('Reconciler: update called');
}
```

**Files Modified**:
- `packages/api/src/reconciler/host-config.ts` (appendChildToContainer)

### Problem 2: UI Not Updating on State Changes

**Symptom**: After the plugin loaded successfully:
1. Clicking the "Count" button didn't increment the displayed number
2. Clicking "Submit" button had no effect
3. Clicking "Reset" button didn't clear the input field
4. Console logs confirmed onClick handlers were being called
5. React state was updating (verified via React DevTools or logs)

**Root Cause**: Svelte 5's fine-grained reactivity issue with object mutations.

When React state changed and triggered a re-render:
1. React reconciler's `commitUpdate` function correctly updated `instance.props` with new values
2. However, the `rootInstance` object *reference* remained the same
3. Svelte 5's reactivity system tracks signals at the assignment level
4. Since `rootInstance` was only assigned once during initial mount, subsequent property mutations on nested objects didn't trigger Svelte re-renders
5. The `resetAfterCommit` hook was being called but NOT calling `update()` - it had a comment saying "Don't call update() here"

**Why This Happened**: 
- In Svelte 5, `$state` creates fine-grained reactivity
- Mutating nested properties of a state object doesn't automatically trigger updates
- The reconciler was mutating `rootInstance.props` and child properties without creating a new reference
- The PluginHost component had no way to know the tree had changed

**Options Considered**:

1. **Deep clone rootInstance on every update** ❌
   - Would work but expensive for large component trees
   - Breaks object identity/references
   - Poor performance

2. **Use Svelte stores instead of $state** ❌
   - Would require major refactor
   - Doesn't solve the fundamental problem
   - More boilerplate

3. **Version counter + {#key} block** ✅ **CHOSEN**
   - Lightweight: single counter increment
   - Forces Svelte to recreate component tree when needed
   - Simple to understand and maintain
   - Standard Svelte pattern for forcing re-renders

4. **Call update() on every commit + use version tracking** ✅ **ALSO NEEDED**
   - The `resetAfterCommit` hook is called after every React commit
   - This includes prop updates from state changes
   - We weren't calling `update()` there

**Solution Implemented**:

**Step 1**: Enable update notifications on every commit
```typescript
// packages/api/src/reconciler/host-config.ts
resetAfterCommit(container: Container): void {
  console.log('Reconciler: resetAfterCommit - calling update()');
  // Call update after any commit to notify Svelte of changes
  container.update();
}
```

**Step 2**: Add version counter to bridge
```typescript
// packages/api/src/reconciler/bridge.ts
export interface SimpleRenderBridge {
  rootInstance: SvelteComponentInstance | null;
  version: number;  // NEW
  subscribers: Set<() => void>;
  subscribe: (callback: () => void) => () => void;
  update: () => void;
}

update() {
  bridge.version++;  // Increment on every update
  bridge.subscribers.forEach(callback => callback());
}
```

**Step 3**: Track version in PluginHost and use {#key} to force re-render
```svelte
<!-- packages/app/src/plugin/PluginHost.svelte -->
<script>
  let version = $state(0);
  
  unsubscribe = newBridge.subscribe(() => {
    version = (newBridge as any).version;  // Update local version
    rootInstance = newBridge.rootInstance;
  });
</script>

<div class="w-full h-full">
  {#if rootInstance}
    {#key version}
      <ComponentRenderer instance={rootInstance} />
    {/key}
  {:else}
    <div>Loading plugin…</div>
  {/if}
</div>
```

**How It Works**:
1. React state changes (e.g., count increments)
2. React reconciler runs and updates instance props
3. `resetAfterCommit` is called
4. Bridge's `update()` increments version and notifies subscribers
5. PluginHost's subscription callback updates local `version` state
6. Svelte's `{#key version}` block detects the version change
7. ComponentRenderer is destroyed and recreated with fresh props
8. UI reflects the new state

**Files Modified**:
- `packages/api/src/reconciler/host-config.ts` (resetAfterCommit)
- `packages/api/src/reconciler/bridge.ts` (added version property)
- `packages/app/src/plugin/PluginHost.svelte` (version tracking + {#key} block)

### Technical Insights

**Svelte 5 Reactivity Model**:
- `$state` creates signals that track assignments
- Nested property mutations don't trigger reactivity
- `{#key}` blocks force recreation when the key value changes
- This is similar to React's key prop but for controlling component lifecycle

**React Reconciler Lifecycle**:
- `createInstance` - creates component instances
- `appendChildToContainer` - mounts root to container (called once)
- `commitUpdate` - updates instance props (called on re-renders)
- `resetAfterCommit` - cleanup/finalization after commit phase (called on every commit!)

**Bridge Pattern**:
The bridge acts as a synchronization layer:
1. Holds the component tree (rootInstance)
2. Provides subscription mechanism for updates
3. Version counter provides a "checksum" for change detection
4. Subscribers (PluginHost) react to updates and trigger Svelte re-renders

### Performance Considerations

**Current Approach**: Using `{#key version}` causes full component tree recreation on every React update.

**Pros**:
- Simple and reliable
- Easy to understand and maintain
- Works with any component tree structure
- No special handling needed for different component types

**Cons**:
- More expensive than fine-grained updates
- Destroys and recreates DOM elements
- Loses component-level state (though plugin uses React state)

**Future Optimization Options** (if needed):
1. Implement fine-grained prop comparison in ComponentRenderer
2. Use Svelte stores for deep reactivity
3. Track "dirty" instances and only update those
4. Implement reconciliation at the Svelte level (complex)

**Decision**: Start with {#key} approach because:
- Plugins are typically small UIs (buttons, inputs, forms)
- Performance is acceptable for this use case
- Premature optimization is root of all evil
- Can optimize later if profiling shows issues

### Lessons Learned

1. **Async timing issues are subtle**: The setTimeout approach seemed reasonable but created hard-to-debug timing problems
2. **Framework reactivity models differ**: What works in React doesn't directly translate to Svelte 5's fine-grained reactivity
3. **Reconciler lifecycle hooks matter**: Understanding when each hook is called is critical for bridging frameworks
4. **Simple solutions first**: Version counter + {#key} is simpler than deep cloning or complex diffing
5. **Console logging saves time**: Strategic logging in reconciler and components quickly revealed the issues
